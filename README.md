# Project L.O.V.E.

## Location Operations & Virtualized Edge

Project L.O.V.E. is an AWS edge-to-cloud operations project that simulates a Linux-based edge device deployed at a remote physical location.

The project demonstrates how an edge workload can securely generate telemetry, publish operational data through AWS IoT Core, store telemetry in Amazon S3, stream logs and metrics into Amazon CloudWatch, trigger operational alerts through Amazon SNS, recover automatically from service failures using systemd, and manage AWS infrastructure with Terraform.

The goal of Project L.O.V.E. is to demonstrate practical Cloud Engineering, DevOps, Infrastructure as Code, IoT, monitoring, incident response, and Linux operations skills in one end-to-end environment.

## Project Goals

- Simulate a remote Linux edge device
- Generate operational telemetry continuously
- Connect the edge device securely to AWS IoT Core
- Route telemetry into AWS services
- Store telemetry in Amazon S3
- Centralize operational logs in Amazon CloudWatch
- Create health metrics and alarms
- Send operational alerts through Amazon SNS

# AWS Services Used

AWS IoT Core provides the connection between the simulated edge device and the AWS cloud environment.

The edge publisher communicates through MQTT using the Project L.O.V.E. telemetry topic.

IoT rules process incoming telemetry and route it to downstream AWS services.

## CloudWatch Heartbeat Alarm

Project L.O.V.E. includes a CloudWatch alarm designed to detect when telemetry stops arriving.

Alarm:

```text
ProjectLOVE-Heartbeat-Alarm
```

The alarm monitors the custom heartbeat metric:

```text
TelemetryHeartbeat
```

When telemetry stops for the configured evaluation period, CloudWatch changes the alarm state from:

```text
OK
```

to:

```text
ALARM
```

When telemetry resumes, the alarm automatically returns to:

```text
OK
```

This provides a basic operational health check for the edge device.

---

## Amazon SNS

Amazon SNS provides the notification layer for operational alerts.

SNS topic:

```text
ProjectLOVE-Alerts
```

The CloudWatch heartbeat alarm sends notifications through this topic whenever the simulated edge device stops sending telemetry.

# Linux Service Management

The Project L.O.V.E. edge publisher runs as a Linux systemd service.

Service:

```text
project-love-edge.service
```

The service automatically starts the Python telemetry publisher and restarts it if the application unexpectedly fails.

The service configuration is stored in:

```text
systemd/project-love-edge.service
```

Example configuration:

```ini
[Unit]
Description=Project L.O.V.E. Edge Telemetry Publisher
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=cloudsystemsdirect
Group=cloudsystemsdirect
WorkingDirectory=/home/cloudsystemsdirect/project-love
ExecStart=/home/cloudsystemsdirect/project-love/venv/bin/python /home/cloudsystemsdirect/project-love/edge_device.py
Restart=on-failure
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

---

# Installing the systemd Service

Copy the service definition:

```bash
sudo cp systemd/project-love-edge.service /etc/systemd/system/
```

Reload systemd:

```bash
sudo systemctl daemon-reload
```

Enable the service at startup:

```bash
sudo systemctl enable project-love-edge
```

Start the service:

```bash
sudo systemctl start project-love-edge
```

Verify status:

```bash
sudo systemctl status project-love-edge
```

View telemetry logs:

```bash
sudo journalctl -u project-love-edge -f
```

Restart the service:

```bash
sudo systemctl restart project-love-edge
```

Stop the service:

```bash
sudo systemctl stop project-love-edge
```

---

# Automatic Recovery

The systemd configuration includes:

```ini
Restart=on-failure
RestartSec=5
```

This allows the Linux operating system to automatically restart the edge telemetry process after an unexpected application failure.

This simulates a common production requirement for remote edge devices where manual intervention may not be immediately available.

# Controlled Incident Test

A controlled outage was performed to validate the monitoring and recovery workflow.

## Normal Operation

The Linux edge service was running and continuously publishing telemetry.

```bash
sudo systemctl status project-love-edge
```

CloudWatch reported:

```text
OK
```

Telemetry continued arriving in Amazon S3.

---

## Simulated Outage

The edge service was intentionally stopped:

```bash
sudo systemctl stop project-love-edge
```

Telemetry stopped arriving.

After the configured evaluation period, the CloudWatch heartbeat alarm transitioned:

```text
OK
   |
   v
ALARM
```

This demonstrated that AWS monitoring could detect loss of communication from the edge device.

---

## Recovery

The edge service was restarted:

```bash
sudo systemctl start project-love-edge
```

Telemetry resumed.

New objects began arriving in Amazon S3.

CloudWatch then transitioned:

```text
ALARM
   |
   v
OK
```

This verified the complete monitoring and recovery lifecycle.

# Security

Project L.O.V.E. follows several basic cloud security practices.

## IAM

Dedicated IAM roles and policies are used for AWS IoT service actions.

Permissions are separated between:

- IoT
- S3
- CloudWatch

---

## S3 Security

The telemetry bucket uses:

- Public access blocking
- Server-side encryption
- IAM-controlled access

---

## IoT Security

AWS IoT Core uses device certificates for authenticated MQTT communication.

Private certificates are excluded from source control.

---
